

# Prompts

The entrypoint for turning a rough prompt into a sharp one, and the place to stack Juss's overlays when he wants more than one applied at once.

## Two ways in — this is the point
- **Singular:** need just one register? Call that overlay directly (`/hormozi`, `/80-20`, `/humanize`, ...). It's a standalone skill. Don't route through here for a single pass.
- **Stacked:** need several? Call this skill, or name the ones you want. It applies them together, in order, so they refine rather than fight each other.

## Prompt-rewrite workflow
When the task is to improve a prompt:
1. Identify the real goal — what output is actually wanted.
2. Strip vague language.
3. Add the missing context, constraints, and success criteria.
4. Choose which overlays fit (or apply the ones named).
5. Return a prompt that's shorter, sharper, and easier to execute.

Prefer this shape for the rewritten prompt: goal, context, constraints, output format, quality bar.

## The overlay roster
Reasoning: **first-principles** (rebuild from fundamentals), **socrates** (surface assumptions).
Prioritization: **80-20** (cut to what matters), **futureyou** (optimize the durable call).
Delivery: **hormozi** (outcome-first, sharp), **humanize** (sound like an actual person).
Constant: **truthmode** (accuracy over comfort) and **antiadvice** (no empty clichés) can ride along with anything.

## Stacking order
When several are stacked, apply them in this sequence — earlier stages shape the substance, later stages shape how it reads:
1. **Reasoning first** — first-principles, socrates. Get the thinking right before dressing it up.
2. **Then prioritize** — 80-20, futureyou. Cut to what matters and what lasts.
3. **Then deliver** — hormozi, humanize. Shape the register and the voice last.
4. **truthmode and antiadvice run throughout**, not as a step — they're honesty constraints on every stage.

Applying delivery overlays before reasoning ones is how you get polished text that says nothing. Substance first, shine last.
