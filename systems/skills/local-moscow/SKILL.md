

# MoSCoW

Draw the line for one release. Four buckets — and the discipline is honesty about which one things really belong in.

- **Must** — ship is meaningless without it. If it slips, the release doesn't go. Keep this list short; everything feels like a Must until you're forced to cut.
- **Should** — important, painful to leave out, but the release still works without it. First in line for the next pass.
- **Could** — nice, low-cost, include only if time allows. First thing sacrificed when the deadline tightens.
- **Won't** — explicitly out of scope for THIS release. Naming it here is what stops it creeping back in mid-build.

## How to use it
- Force-rank into the four buckets. Resist a bloated Must list — if everything's critical, nothing is.
- State in one line why each Must is truly non-negotiable.
- Treat the Won't list as the point, not an afterthought — it's the fence that protects the release from scope creep.
- When you're unsure, pair with 80-20: it tells you where the impact is, MoSCoW tells you what makes the cut. Different questions.
